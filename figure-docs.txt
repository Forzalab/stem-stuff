<topic id="points" title="Points" use="use when you place or derive points (midpoints, feet, rotations, intersections)">
Points (all computed by the engine, world units, y up):
- Pt(x, y): a free point. The only kind a pass-2 Fix may move.
- Mid(A, B): midpoint.
- Along(A, B, t): A + t (B - A); t = 0.5 is the midpoint, t > 1 runs past B.
- Off(P, dx, dy): P shifted by (dx, dy).
- Foot(P, A, B): the foot of the perpendicular from P onto line AB (an altitude's foot).
- Rot(O, P, deg): P turned about O by deg, counter-clockwise. Rot(P, Off(P, 0, 1), 30) is a unit normal of a 30 degree slope, set at P.
- Meet(A, B, C, D): where line AB meets line CD. Parallel lines have no point: that is an error.
Derive points from each other so a change to one anchor moves everything that hangs off it.
```
A = Pt(0, 0)
B = Pt(6, 0)
C = Pt(2, 4)
M = Mid(A, B)
H = Foot(C, A, B)
T = Meet(A, Rot(A, B, 30), B, Off(B, 0, 1))
tri = Poly([A, B, C], {kind: "overlay"})
alt = Seg(C, H, {kind: "overlay", tone: "violet"})
```
</topic>

<topic id="shapes" title="Shapes" use="use when you draw a body, line, box, polygon, circle, vector, label or angle">
Shapes (centre-based, world units):
- Seg(A, B, opts?): a line (wire, rod, rope, ground). Thin: lines never conflict with each other.
- Box(C, w, h, deg?, opts?): a w x h rectangle centred on C, turned deg counter-clockwise.
- Poly([A, B, C, ...], opts?): a polygon (convex or not).
- Circle(O, r, opts?).
- Vec(A, B, label?, opts?): a vector arrow from A to B (force, velocity, current, pointer). Head at B.
- Label(P, text, opts?): text centred on P when free, else moved nearby by the engine.
- Angle(A, O, B, label?, opts?): an arc at O between rays OA and OB, with its label.
A body resting on a slope: take a point P on the slope, the centre is P + normal * h/2:
```
A = Pt(0, 0)
B = Pt(6, 0)
top = Meet(A, Rot(A, B, 25), B, Off(B, 0, 1))
ramp = Poly([A, B, top], {kind: "surface"})
P = Along(A, top, 0.5)
C = Rot(P, Off(P, 0, 0.5), 25)
blk = Box(C, 1, 1, 25, {fill: true})
```
</topic>

<topic id="kinds" title="Kinds and findings" use="use when you pick a kind (solid, surface, inside, overlay) or read a layout finding">
Kinds decide what the engine checks (layout only; never physics meaning):
- solid (default for Seg Box Poly Circle): two solids may touch but not overlap beyond the tolerance (1% of the figure span).
- surface: a one-sided floor, wall, ramp or face. Bodies rest on it; sinking in is an error. Vec heads may end inside it.
- inside + in: id: stays inside its container (a Box, Poly or Circle); it may fill it exactly. Still solid against other shapes.
- overlay: never checked. Use it for lines that join bodies (a tree edge centre to centre), construction lines, curves drawn over strips.
- decor (Vec, Label, Angle, automatic): labels are never checked; a Vec is checked only at its head, against solids it does not start in.
Findings come back as pairs ids [later, earlier]: the later line is blamed, with the amount and the push vector (where it must move).
A dashed ghost shows where the later shape would have to go.
</topic>

<topic id="curves" title="Curves and unions" use="use when a part is organic or one object is made of several parts">
Curves and unions (organic parts: a beak, a horn, a tail, a lens, a field line). Prefer Box / Circle / Poly; reach for Curve only when a part is round or organic.
- Curve([A, B, C, ...]): a smooth curve through every point (centripetal Catmull-Rom). The drawn curve and the checked outline are the same polyline.
- closed: true closes it into a blob (an area: it collides, it can be filled, a label can sit inside).
- w: 0.3 (a stroke 0.3 wide) or w: [0.4, 0.05] (tapered from 0.4 to 0.05, round ends): a horn, a beak, a tail, a neck. Open curves only.
- mirror: [P, Q] adds the mirror image of the points across line PQ, joined at the axis: give half a symmetric outline.
- An open Curve without w is a thin line (a path, a trajectory, a ripple): lines never conflict with lines.
- A curve that crosses itself is an error: move a point, or make the stroke thinner at a tight bend.
- Union([a, b, c], opts?): one object made of parts. Parts collide with OTHER objects, never with each other. The Union's legend / label name the whole group; its kind, tone, shade, fill fill in what a part leaves out (a part's own opts win).
Build organic things like a human in Canva: the prefix holds rough blocks, a Layer swaps them for the detailed parts.
```
G = Pt(0, 0)
ground = Seg(Off(G, -4, 0), Off(G, 4, 0), {kind: "surface", tone: "muted"})
cube = Box(Off(G, 0, 2), 4, 4, 0)
s1 = Layer([f1], {title: "The cube"})
f1 = Fix(cube, {tone: "amber", fill: true})
s2 = Layer([horn, beast], {lit: [horn], zoom: [horn], title: "Add a horn"})
horn = Curve([Off(G, -0.6, 4), Off(G, -0.3, 5), Off(G, 0.6, 5.9)], {w: [0.9, 0.05], fill: true, tone: "violet"})
beast = Union([cube, horn], {legend: "horned cube"})
```
Symmetric lens with mirror (half the outline, mirrored across the vertical through O):
```
O = Pt(0, 0)
lens = Curve([Off(O, 0, 2.5), Off(O, 0.4, 0), Off(O, 0, -2.5)], {closed: true, mirror: [O, Off(O, 0, 1)], fill: true, tone: "sky", shade: 3})
```
</topic>

<topic id="legend" title="Legend and labels" use="use when an object needs a name or a short symbol or value">
Legend: names of objects go under the drawing, beside a small render of the object itself (not a colour swatch).
- legend: "elephant" on a shape (or on a Union: the render shows every part). Use it for what an object IS: elephant, students, oil, lens.
- label: "m" is for a short symbol or value ON the object (m, 2 Ω, A). The engine puts it inside the shape when it fits, else right beside it.
- A label with no room inside or right next to its anchor (it would cross a line, a filled body or another label) moves to the legend by itself: the feedback says "moved to legend". No leader lines are drawn.
```
G = Pt(0, 0)
floor = Seg(Off(G, -3, 0), Off(G, 3, 0), {kind: "surface", tone: "muted"})
crate = Box(Off(G, -1.2, 0.6), 1.2, 1.2, 0, {fill: true, tone: "sky", label: "m", legend: "crate"})
body = Circle(Off(G, 1.4, 0.9), 0.9, {fill: true})
ear = Circle(Off(G, 2.3, 1.5), 0.4, {fill: true})
cat = Union([body, ear], {tone: "muted", legend: "cat"})
```
</topic>

<topic id="dim" title="Dimensions" use="use when you show a length, radius, height or distance">
Dim(A, B, text, opts?): a dimension line for the length AB: drawn beside AB on the outside of the figure, with a tick at each end and the text centred along it (or just beside it when the line is short).
- The engine tries the outside, then the other side, then further out; if no spot is free the text moves to the legend.
- A and B can be any points: Dim(Off(O, 0, 0), Off(O, 4, 0), "4 m") under a body, Dim(Foot(C, A, B), C, "h") for a height.
- Use Dim for lengths, radii, distances and heights. Never a loose Label for a length.
```
A = Pt(0, 0)
B = Pt(5, 0)
C = Pt(1.5, 3)
tri = Poly([A, B, C], {kind: "overlay", tone: "ink"})
H = Foot(C, A, B)
alt = Seg(C, H, {kind: "overlay", tone: "violet"})
b = Dim(A, B, "b = 5 cm")
h = Dim(H, C, "h = 3 cm", {tone: "violet"})
```
</topic>

<topic id="layers" title="Steps and layers" use="use when the drawing needs ordered reasoning steps">
Layers stack steps, like Photoshop layers that cannot be switched off in the middle (linear, no branches).
- Plan first: // goal, // anchor, // layers: 1 <idea>, 2 <idea>, // budget: N statements. The engine compares the plan with what is drawn.
- One layer = one reasoning step that changes what the student looks at; pure algebra stays in the text. 2-4 layers, at most 6.
- HINT mode stops before the answer layer; EXPLAIN includes it.
- The prefix = every line before the first Layer: the anchor's rough blocks only, drawn as a blueprint.
- sN = Layer([ids...], opts) adds those statements (and every line written after it, until the next Layer) on top of all before it.
- hide: [ids] hides earlier shapes from this step on (swap a rough block for its detailed parts).
- lit: [ids] = where to look: the rest of the figure turns pale. zoom: [ids] = the camera fits those shapes for this step.
- title: "..." = one short line for the step. A Fix listed in a Layer restyles from that step on (step 1 tone amber).
- Checks: each step's new shapes are checked against everything shown with them; shapes never shown together never conflict.
```
// goal: why the block stays put, then what a push adds
// anchor: a block on the floor
// layers: 1 weight and normal force, 2 the push
// budget: 8 statements
O = Pt(0, 0)
floor = Seg(Off(O, -3, 0), Off(O, 3, 0), {kind: "surface", tone: "muted"})
blk = Box(Off(O, 0, 0.75), 1.5, 1.5, 0, {fill: true, tone: "muted"})
s1 = Layer([W, N], {lit: [W, N], title: "Two forces"})
W = Vec(Off(O, 0, 0.75), Off(O, 0, -1), "W", {tone: "sky"})
N = Vec(Off(O, 0, 0.75), Off(O, 0, 2.5), "N", {tone: "amber"})
s2 = Layer([F], {lit: [F], zoom: [blk, F], title: "Push it"})
F = Vec(Off(O, -2.6, 0.75), Off(O, -0.75, 0.75), "F", {tone: "violet"})
```
</topic>

<topic id="pass2" title="Reviews and Fix" use="use when you answer a review or patch a point or shape">
Reviews (pass 2) append lines; they never delete.
- Fix a free point or a shape's own traits with a PATCH holding only what changes:
  f1 = Fix(C, {x: 1.2})            moves Pt C, and everything derived from it follows
  f2 = Fix(blk, {w: 1.4, deg: 30}) Box traits w h deg; Circle r; Label text; Vec and Angle label; any shape's opts keys
- Fix on a derived point (Mid Along Off Foot Rot Meet) is an error: fix its free source Pt instead.
- New statements may be added (new ids). Redefining an old id is an error; to delete or restructure, rewrite pass 1.
- After a review everything is evaluated and checked again.
Review 1 = geometry: answer each finding with a Fix (use the ghost target). Reviews 2 and 3 = meaning: add or adjust what the scene shows.
If nothing needs changing, reply with the single line: // ok
</topic>

<topic id="colors" title="Colors and shade" use="use when you pick a tone, shade or fill">
Colors: palette hues only, one hue per quantity, kept across the figure and the text.
tone: sky amber orange violet pink cyan (quantities), ink (structure), muted (context, surfaces, wires). No green, no red.
shade: 1 = asked (the unknown), 2 = given, 3 = implied or context. fill: true fills an area shape (a face, a liquid).
Vec and Label without a tone get their own hue automatically; structure without a tone is ink.
```
O = Pt(0, 0)
v = Vec(O, Pt(3, 0), "v", {tone: "sky", shade: 2})
a = Vec(O, Pt(0, 2), "a = ?", {tone: "amber", shade: 1})
```
</topic>

<example id="ex-area-tangent" topic="math" tags="curve,tangent,area,slope" title="Area under a curve and the tangent at P" use="use when the problem asks for a slope at a point or the area under a curve" inline="1" more="ex-unit-circle ex-riemann">
A smooth curve y = f(x) with a point P on it, the tangent at P, and the area under f from x = a to x = b shaded.
```
// goal: read the slope at P and the area under f between a and b
// anchor: the curve y = f(x) above the x axis
// layers: 1 the curve and P, 2 the tangent at P, 3 the shaded area
// budget: 20 statements
O = Pt(0, 0)  // one free origin: every axis point is derived from it
xAxis = Seg(O, Off(O, 6, 0), {tone: "muted"})  // x axis: muted context, so it never competes with f
yAxis = Seg(O, Off(O, 0, 4), {tone: "muted"})  // y axis: same muted stroke, one hue for structure
A = Pt(1, 0)  // a is a free anchor: the area, the Dim and f all hang off it
B = Pt(5, 0)  // b is free too, so b - a is one span a Fix can move
s1 = Layer([f, dotP], {title: "The curve and P"})  // step 1 adds the curve and the point; a Layer is one reasoning step
T1 = Off(A, 0, 0.6)  // f at a: Off A, not a raw Pt, so moving a drags the curve with it
T2 = Off(A, 1, 1.1)  // next sample: one unit right, height off the same anchor
P = Off(A, 2, 1.5)  // P is a control point of f, so it lies on the curve exactly
T4 = Off(A, 3, 2.1)  // sample after P: keeps the rise smooth, no extra anchor
T5 = Off(A, 4, 2.8)  // f at b: last control point, again derived from A
f = Curve([T1, T2, P, T4, T5], {tone: "amber"})  // open Curve is a thin line: it never collides with the area
dotP = Circle(P, 0.07, {kind: "overlay", fill: true, tone: "violet"})  // a dot at P is a helper mark, so overlay, never solid
s2 = Layer([tan], {title: "The tangent at P"})  // step 2 adds one construction line on top of step 1
Q = Off(P, 1, 0.5)  // tangent direction: slope 0.5 as a step from P, no raw Pt
tan = Seg(Along(P, Q, -1.3), Along(P, Q, 1.3), {kind: "overlay", tone: "violet"})  // Along both ways keeps the line centred on P; overlay because a tangent is a helper line over the area
s3 = Layer([area], {title: "The shaded area"})  // step 3 adds the region: the step that answers the area question
area = Poly([A, T1, T2, P, T4, T5, B], {fill: true, tone: "sky", shade: 3})  // a real region stays solid, not overlay; shade 3 = context
dim = Dim(A, B, "b - a", {tone: "muted"})  // Dim, not a Label: a width gets ticks and sits outside; written last, so the later line yields to the shapes already there
lab = Label(Off(T5, 0.25, 0.2), "f(x)", {tone: "amber"})  // symbol only: f(x), never a value the student must find
```
</example>


<example id="ex-unit-circle" topic="math" tags="unit circle,sin,cos,right triangle" title="Math: unit circle, sin and cos" use="use when the problem is the unit circle, or cos and sin as the coordinates of a point">
The unit circle with the angle θ at the centre O and the point P on the circle; the cos leg lies on the x-axis, and the sin leg stands on it at the foot.
```
// goal: read cos θ and sin θ as the two coordinates of P on the unit circle
// anchor: the unit circle, its centre O and the point P at θ
// layers: 1 the circle and P, 2 the sin leg, 3 the cos leg
O = Pt(0, 0)  // the centre: the one free anchor, and the only point a review may move
xAx = Seg(Off(O, -1.15, 0), Off(O, 1.15, 0), {kind: "overlay", tone: "muted", shade: 3})  // the x-axis: a helper line through the centre, overlay because it is construction, not a body
yAx = Seg(Off(O, 0, -1.15), Off(O, 0, 1.15), {kind: "overlay", tone: "muted", shade: 3})  // the y-axis: the same helper role as xAx, so overlay and muted too
R = Off(O, 1, 0)  // the radius direction: Off, not a raw Pt, so R stays exactly one unit from O
s1 = Layer([circ, rad, dot, th], {lit: [circ, rad, dot, th], title: "The circle and the point P"})  // one layer is one reasoning step: the given circle and point first, so every later leg is read against them
circ = Circle(O, 1, {tone: "ink", shade: 2, legend: "unit circle"})  // the unit circle is the real object, so it keeps the default solid kind; fill off draws only its outline, and the legend names the object itself, not a colour key
P = Rot(O, R, 35)  // P at θ: Rot, not a raw Pt, so changing the angle turns P and every leg that hangs off it
rad = Seg(O, P, {kind: "overlay", tone: "ink", shade: 2, label: "1"})  // the radius OP: an overlay construction line; label "1" is the given unit radius, not an answer
dot = Circle(P, 0.06, {kind: "overlay", fill: true, tone: "ink"})  // a marker at P: overlay because a point mark is not a body
th = Angle(R, O, P, "θ")  // the angle at O: Angle, not a text Label, so the arc marks exactly the angle between OR and OP
s2 = Layer([sinL, rt1, rt2, dS], {lit: [sinL, rt1, rt2, dS], title: "sin θ: the height of P"})  // one reasoning step: drop the perpendicular, and sin θ appears as the height
Q = Foot(P, O, R)  // the foot on the x-axis: Foot, not a raw Pt, so it stays under P when θ changes
sinL = Seg(Q, P, {kind: "overlay", tone: "violet"})  // the sin leg: the vertical rise Q to P; overlay because it is a construction mark on the disc, and a plain Seg because dS carries the measure
rt1 = Seg(Off(Q, -0.09, 0), Off(Q, -0.09, 0.09), {kind: "overlay", tone: "muted"})  // one side of the right-angle square at Q: a helper mark, overlay because it is construction, not a body
rt2 = Seg(Off(Q, -0.09, 0.09), Off(Q, 0, 0.09), {kind: "overlay", tone: "muted"})  // the other side of the square: with the two legs it closes the right angle at the foot
dS = Dim(Q, P, "sin θ", {tone: "violet"})  // sin θ as a length: Dim, not a Label, because Dim draws the measure beside the leg with a tick at each end

lT1 = Off(G, -2, 4)  // outer top-right; lB1 to lT1 is the open mouth the bridge will pass through
rB0 = Off(G, 2, 0)  // right beaker's outer bottom-left, mirrored from the left one
rB1 = Off(G, 6, 0)  // outer bottom-right of the right beaker
rT0 = Off(G, 2, 4)  // outer top-left of the right beaker
rT1 = Off(G, 6, 4)  // outer top-right; its open mouth
lspace = Poly([lB0, lB1, lT1, lT0], {kind: "overlay", tone: "muted", shade: 3})  // the beaker's inner space is only an `in:` target, so overlay: it is a helper container and must never collide; shade 3 says context
rspace = Poly([rB0, rB1, rT1, rT0], {kind: "overlay", tone: "muted", shade: 3})  // the right beaker's inner space, same helper role, so each liquid is checked against its own container
wl1 = Seg(lB0, lT0, {kind: "surface", tone: "ink"})  // glass is a real one-sided boundary, so surface: the liquid rests against it and may not sink in; ink because glass is structure, not a quantity
wb1 = Seg(lB0, lB1, {kind: "surface", tone: "ink"})  // the base is a surface too, so the liquid sits on it instead of overlapping it
wr1 = Seg(lB1, lT1, {kind: "surface", tone: "ink"})  // the right wall closes the U shape; three surfaces draw a beaker without enclosing a solid area
wl2 = Seg(rB0, rT0, {kind: "surface", tone: "ink"})  // the right beaker's left wall, a surface and never a solid block the liquid would have to dodge
wb2 = Seg(rB0, rB1, {kind: "surface", tone: "ink"})  // its base, so the second liquid also rests on glass
wr2 = Seg(rB1, rT1, {kind: "surface", tone: "ink"})  // its right wall
solL = Poly([lB0, lB1, Off(lB1, 0, 2.5), Off(lB0, 0, 2.5)], {kind: "inside", in: lspace, fill: true, tone: "sky", shade: 2})  // the solution has volume, so inside + in: lspace proves it stays in the beaker; sky shade 2 marks a given liquid
solR = Poly([rB0, rB1, Off(rB1, 0, 2.5), Off(rB0, 0, 2.5)], {kind: "inside", in: rspace, fill: true, tone: "sky", shade: 2})  // the copper half-cell's solution, inside its own container so the two liquids cannot mix
s1 = Layer([zn, cu], {lit: [zn, cu], title: "Two electrodes"})  // one Layer is one reasoning step, and the first step is the pair of metals that exchange electrons
zn = Box(Off(Mid(lB0, lB1), 0, 3.5), 0.4, 2, 0, {fill: true, tone: "violet", shade: 2, legend: "Zn"})  // the zinc strip stands at Mid of its beaker floor and is lifted by Off until its foot touches the solution top (contact, not overlap); legend, not label, because Zn is the object's name
cu = Box(Off(Mid(rB0, rB1), 0, 3.5), 0.4, 2, 0, {fill: true, tone: "orange", shade: 2, legend: "Cu"})  // the copper strip, mirrored by the same Mid + Off; a second hue marks the second metal
s2 = Layer([bridge], {lit: [bridge], title: "Salt bridge"})  // the next step is the internal path: ions move only once the bridge joins the two solutions
bridge = Curve([Off(G, -3.3, 2.6), Off(G, -3.3, 3.6), Off(G, -3.2, 4.9), Off(G, -1.8, 5.35), Off(G, 0, 5.45), Off(G, 1.8, 5.35), Off(G, 3.2, 4.9), Off(G, 3.3, 3.6), Off(G, 3.3, 2.6)], {w: 0.35, fill: true, tone: "pink", shade: 2, legend: "salt bridge"})  // a thick Curve, not a Seg, because the bridge is a tube; its ends stop on the solution surfaces, and as the later line it is the bridge that yields to the beakers; legend names it
s3 = Layer([wire, flow], {lit: [wire, flow], title: "Wire and electrons"})  // the last step is the external path, which is what turns the two half-cells into a circuit
w1 = Seg(Off(G, -4, 4.5), Off(G, -4, 6), {kind: "overlay", tone: "muted"})  // a connector from the zinc top up into the wire; overlay because it joins bodies instead of being a body itself
w2 = Seg(Off(G, -4, 6), Off(G, 4, 6), {kind: "overlay", tone: "muted"})  // the run across the gap; overlay keeps this helper line out of every collision check
w3 = Seg(Off(G, 4, 6), Off(G, 4, 4.5), {kind: "overlay", tone: "muted"})  // down to the copper top; overlay lets the wire meet the electrode exactly at the joint
wire = Union([w1, w2, w3], {kind: "overlay", tone: "muted"})  // the three Segs are one wire, so Union groups them as one object made of parts; overlay marks the whole connector unchecked, never a real body
flow = Vec(Off(G, -2.5, 6), Off(G, -0.5, 6), "e⁻", {tone: "cyan"})  // electrons leave Zn and reach Cu, so the arrow points Zn to Cu; a Vec is decor, checked only at its head, and the head sits in open air
```

<example id="ex-dijkstra" topic="cs" tags="dijkstra,shortest-path,weighted-graph" title="CS: Dijkstra shortest path" use="use when the problem is the shortest path in a weighted graph" inline="1" more="ex-bst-insert ex-cs">
A weighted graph rooted at the start node S, then the tentative distances beside the nodes, then the shortest path S to T lit:
```
// goal: the shortest path S to T, built up in Dijkstra steps
// anchor: the graph, rooted at the start node S
// layers: 1 the graph, 2 tentative distances, 3 the shortest path lit
// budget: 28 statements
S = Pt(0, 0)                                              // the one free Pt: every node is Off it, so a Fix on S moves the whole graph
sn = Circle(S, 0.45, {tone: "sky", shade: 2, label: "S"})  // a node is a Circle; "S" is a symbol, and it fits inside so no legend row
s1 = Layer([eSA, eSB, eAB, eAC, eBD, eCT, eDT], {title: "The graph"})  // step 1 adds the graph's body; the prefix holds only the anchor S
T = Off(S, 7, 0)                                          // Off, not Pt(7, 0): T keeps its place relative to S, one anchor moves all
A = Off(S, 2, 2)                                          // derived point, so A cannot drift away from the graph S holds together
B = Off(S, 2, -2)                                         // same Off pattern: the six nodes share one origin, no loose coordinates
C = Off(S, 5, 2)                                          // the far column, still measured from S, not from a second anchor
D = Off(S, 5, -2)                                         // mirrors C about the S-to-T line, so the graph stays readable
eSA = Seg(S, A, {kind: "overlay", tone: "muted", label: "4"})  // overlay: the edge runs under the node circles and lines are never checked
eSB = Seg(S, B, {kind: "overlay", tone: "muted", label: "2"})  // weight as a label on the edge itself, placed by the engine beside it
eAB = Seg(A, B, {kind: "overlay", tone: "muted", label: "2"})  // a short cross edge: it exists to make a second route, nothing more
eAC = Seg(A, C, {kind: "overlay", tone: "muted", label: "3"})  // the top route out of A, one weight per edge
eBD = Seg(B, D, {kind: "overlay", tone: "muted", label: "3"})  // the bottom route out of B, the one the answer will use
eCT = Seg(C, T, {kind: "overlay", tone: "muted", label: "5"})  // every route must end at T, so T collects the last two edges
eDT = Seg(D, T, {kind: "overlay", tone: "muted", label: "4"})  // the second edge into T: the graph offers a choice, the step decides it
nA = Circle(A, 0.45, {tone: "sky", shade: 2, label: "A"})  // the same Circle as S: all nodes read as one kind of object
nB = Circle(B, 0.45, {tone: "sky", shade: 2, label: "B"})  // shade 2 = given: these nodes are data, not the asked value
nC = Circle(C, 0.45, {tone: "sky", shade: 2, label: "C"})  // a short symbol only: never the distance the student must find
nD = Circle(D, 0.45, {tone: "sky", shade: 2, label: "D"})  // keep the labels inside the radius so nothing lands in the legend row
nT = Circle(T, 0.45, {tone: "sky", shade: 2, label: "T"})  // the target node, drawn like the others: the goal is a node, not a special shape
s2 = Layer([dS, dA, dB, dD, dC, dT], {title: "Tentative distances"})  // step 2 adds only numbers: the graph does not change, so no redraw
dS = Label(Off(S, -1, 0), "0", {tone: "amber", shade: 2})  // a Label, not a Dim: an edge weight is not the drawn length, so no dimension line
dA = Label(Off(A, -1.2, 0.3), "4", {tone: "amber", shade: 3})  // shade 3 = context: the best route found so far, still open to change
dB = Label(Off(B, -1.2, -0.3), "2", {tone: "amber", shade: 3})  // Off the node it belongs to: the later line is placed by the earlier one
dD = Label(Off(D, 0, -1), "5", {tone: "amber", shade: 3})  // shade 3 = context: found so far, not yet the answer
dC = Label(Off(C, 0, 1), "7", {tone: "amber", shade: 3})   // the top route's total, kept beside C so the student can compare routes
dT = Label(Off(T, 1.2, 0.5), "?", {tone: "amber", shade: 1})  // shade 1 = asked; "?" is a symbol, never the total the student must find
s3 = Layer([], {lit: [eSB, eBD, eDT], title: "Shortest path"})  // step 3 adds no line at all: lit is the step, the path exists and the rest pales
```
</example>


<example id="ex-bst-insert" topic="cs" tags="bst,insert,comparison path,new leaf" title="CS: binary search tree insert" use="use when a binary search tree insert must show the comparison path and the new leaf">
A seven-node binary search tree; inserting the key 5 compares down from the root and hangs a new leaf.
```
// goal: show where a BST insert goes: compare down from the root, then attach one new leaf
// anchor: the tree, rooted at one raw point
// layers: 1 the tree, 2 the comparison path from the root, 3 the new leaf attached
// budget: 28 statements
O = Pt(0, 0)  // the one raw anchor; every other point is derived from it with Off so the whole tree moves together
root = Off(O, 0, 4.2)  // root centre, one level above the anchor; Off, not a second Pt, keeps it tied to O
L = Off(O, -3, 2.5)  // left child of the root; the drop is wide enough for two node radii to clear
R = Off(O, 3, 2.5)  // right child of the root, mirrored from L so the tree reads as one symmetric object
LL = Off(O, -4.2, 0.8)  // key 2, the left child of 4; derived from O, never typed as its own free point
LR = Off(O, -1.9, 0.8)  // key 6, the right child of 4; the insert will end under this node
RL = Off(O, 1.9, 0.8)  // key 10, the left child of 12; its slot stays empty in this insert
RR = Off(O, 4.2, 0.8)  // key 14, the right child of 12; same level as its siblings
s1 = Layer([n0, n1, n2, n3, n4, n5, n6, e1, e2, e3, e4, e5, e6], {title: "The tree"})  // one layer = one reasoning step: the whole tree first, before any insert moves
n0 = Circle(root, 0.5, {fill: true, tone: "sky", shade: 2, label: "8"})  // a real node body, solid: two nodes may touch but never overlap
n1 = Circle(L, 0.5, {fill: true, tone: "sky", shade: 2, label: "4"})  // keys are givens, so a short symbol label; sky is the existing tree's one hue
n2 = Circle(R, 0.5, {fill: true, tone: "sky", shade: 2, label: "12"})  // same body and tone as its siblings: one hue per quantity across the figure
n3 = Circle(LL, 0.5, {fill: true, tone: "sky", shade: 2, label: "2"})  // drawn as the same solid body; no special kind for a leaf
n4 = Circle(LR, 0.5, {fill: true, tone: "sky", shade: 2, label: "6"})  // the node whose empty left slot will take the new key
n5 = Circle(RL, 0.5, {fill: true, tone: "sky", shade: 2, label: "10"})  // mirror of n3; kept for the shape of the tree, not stepped through
n6 = Circle(RR, 0.5, {fill: true, tone: "sky", shade: 2, label: "14"})  // mirror of n3's sibling; only the left subtree is compared
e1 = Seg(root, L, {kind: "overlay", tone: "muted"})  // a tree edge is overlay: it joins two bodies centre to centre, which a checked solid may not do
e2 = Seg(root, R, {kind: "overlay", tone: "muted"})  // the mirrored edge; muted because an edge is structure, not a quantity
e3 = Seg(L, LL, {kind: "overlay", tone: "muted"})  // same overlay rule: centre to centre, so the nodes stay solid and unchecked against it
e4 = Seg(L, LR, {kind: "overlay", tone: "muted"})  // the second edge the comparison will follow
e5 = Seg(R, RL, {kind: "overlay", tone: "muted"})  // drawn once, never lit: the insert never reaches the right subtree
e6 = Seg(R, RR, {kind: "overlay", tone: "muted"})  // same rule on the far right; symmetry is drawn, not implied
s2 = Layer([p3], {lit: [n0, n1, n4, e1, e4, p3], title: "Follow the comparisons"})  // step 2 changes what the student looks at: lit the chain, the rest pales
slot = Off(O, -2.9, -0.9)  // the empty slot left of 6, derived from O so it hangs exactly one level below LR
p3 = Seg(LR, slot, {kind: "overlay", tone: "amber"})  // a construction probe, so overlay (never checked) and a plain Seg: a Vec tip would end inside the node and be blamed
s3 = Layer([nn, e7], {hide: [p3], lit: [n4, nn, e7], title: "The new leaf"})  // the answer step: HINT stops before it, so the placed key is only drawn here
nn = Circle(slot, 0.5, {fill: true, tone: "amber", shade: 1, label: "5"})  // the inserted key is what was asked, so shade 1; solid like every node
e7 = Seg(LR, slot, {kind: "overlay", tone: "amber"})  // the real edge replaces the probe; written after nn, so line order would blame this edge if it clashed
```
</example>
